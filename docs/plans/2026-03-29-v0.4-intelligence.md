## Design Notes

### #18 Risk Score
`better risk [package...]` or baked into `better doctor`.

Signals (weighted):
- Days since last publish (staleness)
- Open CVEs count (from OSV)
- Maintainer count (bus factor)
- Weekly downloads (popularity proxy)
- Has SECURITY.md, has tests, has CI

Output: `A`–`F` letter grade + numeric 0–100 score + per-signal breakdown.

### #19 Auto-update Intelligence
`better update [--safe] [--changelog]`

Steps:
1. Fetch latest versions for all direct deps
2. Classify: patch / minor / major
3. For patch+minor: fetch CHANGELOG.md / GitHub release notes via npm metadata
4. Score upgrade safety: breaking-change keywords, deprecation notices, test presence
5. Output ranked safe-to-upgrade list; `--apply` actually bumps package.json + runs install

### #20 Bundle Size Impact
`better why <pkg> --size` and `better outdated --size`

- Reads cached CAS sizes to compute total install footprint per package subtree
- Shows: own size, subtree size, % of total node_modules
- In `better outdated`: adds `size_delta` column showing estimated size change on upgrade

### #21 Vulnerability Auto-fix
`better audit --fix [--dry-run]`

Steps:
1. Run OSV scan (existing `better audit`)
2. For each vuln: enumerate versions of affected package that patch the CVE
3. Find highest compatible version satisfying all dependents' semver ranges
4. Produce patch: bump in `package.json` overrides or direct dep bump
5. Run `better install --frozen=false` to apply
6. Re-run audit to confirm fixed
