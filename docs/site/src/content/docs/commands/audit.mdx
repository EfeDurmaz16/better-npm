## Synopsis

```bash
better audit [options]
better audit fix [options]
```

Queries the [OSV.dev](https://osv.dev) batch API for all packages in the lockfile.
Supports npm, Python (PyPI), Rust (crates.io), Ruby (RubyGems), Go, PHP (Packagist),
.NET (NuGet), Swift, and CocoaPods ecosystems.

## Options

| Flag | Default | Description |
|------|---------|-------------|
| `--min-severity` | `low` | Minimum severity to report: `low`, `moderate`, `high`, `critical` |
| `--strict` | `false` | Exit code 2 on any vulnerability (not just high/critical) |
| `--add-ignore CVE-ID` | — | Add a CVE to the ignore list with `--ignore-reason` |
| `--ignore-reason TEXT` | — | Reason for ignoring a CVE (used with `--add-ignore`) |
| `--json` | `false` | Machine-readable JSON output |

## Subcommands

### `better audit fix`

Attempts to automatically upgrade vulnerable packages to their patched version.

```bash
better audit fix
better audit fix --dry-run   # preview changes without applying
```

## Exit Codes

| Code | Meaning |
|------|---------|
| `0` | No vulnerabilities found (or all below `--min-severity`) |
| `2` | Vulnerabilities found at or above `--min-severity` |

## Examples

<Tabs>
<TabItem label="Basic">
```bash
# Audit all packages
better audit

# Only fail on high+ severity
better audit --min-severity high
```
</TabItem>
<TabItem label="CI Integration">
```bash
# In CI: fail build on any vulnerability
better audit --strict --json
```
</TabItem>
<TabItem label="Ignore a known false positive">
```bash
better audit --add-ignore GHSA-abc-123 --ignore-reason "Only affects server-side, not exposed"
```
</TabItem>
</Tabs>
